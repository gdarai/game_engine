# Implementation guide

Use vanilla JavaScript modules, Vite and LittleJS. Keep business logic and geometry in `src/utils`, DOM controls in `src/components`, screen composition in `src/scenes`, and all system-facing operations behind `src/api`. `src/api/index.js` selects the backend: implement the same `isPortrait()`, `getCredentials()`, `setCredentials({ username, password })`, `getStatus()` methods for additional connectors. The web connector stores **only** the username; never save or return a password.

The LittleJS engine is initialized once by the active scene; pass its root element so its canvas stays below the DOM browser layer. Use `src/utils/viewport.js` and `backend.isPortrait()` when sizing it on startup and resize. Render game text using the locally hosted Inter font from `src/assets/fonts`; CSS uses the same family. Keep interactive browser controls accessible and in the lower part of the viewport. Add SVG/PNG border artwork to `src/assets/ninePatch/` rather than generating SVG strings or fetching remote images. `ninePatch.js` selects bundled artwork by filename; `skin.js` applies its slice in pixels to border width, image slice, and image width. The default `double-rounded.svg` uses a 12-pixel slice; supply `skin: { image: 'name.png', slice: 8 }` for another image, with an optional hex `background`. Image colors come from the artwork, and different skins can have different corner sizes.

Shared `src/utils/memory.js` holds the scene name and user-visible error. The scene-level error dialog displays it at the top of the viewport and clears it when clicked; subscribe to state for UI updates and unsubscribe when removing a scene. Surface HTTP, startup and storage failures instead of treating them as success. Login/Create currently only validate both inputs and save the username; do not imply they authenticate.

Keep MSW scenarios and developer controls in `mocks/`; the worker file is served at `/mockServiceWorker.js` by Vite's development-only middleware, not copied into the production build. Add focused Vitest tests beside logic, component and scene code; use `// @vitest-environment jsdom` for browser UI tests, and `msw/node` for HTTP scenarios. Do not rely on a full-app snapshot. Update `README.md`, `AI_README.md`, `API_README.md` and `MOCK_README.md` whenever their respective behavior changes.
